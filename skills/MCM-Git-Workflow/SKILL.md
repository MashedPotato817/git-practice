# MCM Git 协作

## 输入与产物

输入是当前仓库状态、待改文件和任务目标。产物是清楚的分支、可审阅提交、PR 或合并记录，以及可交接的 Git 状态说明。

## 工作流程

1. 开始前检查状态、当前分支、远端和最近提交；确认目标文件和验证方式。
2. 从最新 `main` 新建 `feat/<topic>`、`fix/<topic>`、`docs/<topic>` 或 `chore/<topic>` 分支。
3. 每次提交只处理一个目的；实验性改动可以提交，但说明是否已经验证。
4. 合并前检查结果能复现、文件能交接且不包含赛题、数据或个人信息；使用普通合并保留历史。
5. 同步 `main`、解决冲突或推送前先说明影响范围；不强推共享分支。

## 命名约定

提交信息使用 `<类型>(<可选作用域>): 中文主体`，例如：

```text
docs(workflow): 补充交接检查项
feat(model): 增加基线求解入口
fix(data): 修正单位转换
```

## 人工确认点

- 是否可以合入 `main`，由实际使用过成果的队员确认。
- 推送、删除远端分支、强推或改写历史前，确认远端影响。
- 发生冲突时先理解双方意图，再手动整合，不能机械保留任一方。
